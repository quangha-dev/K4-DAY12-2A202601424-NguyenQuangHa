C
Cấu hình production trên VPSMỗi lớp giải quyết một rủi ro riêng
SSH & deploy user

Dùng tài khoản deploy-day12 và SSH key riêng cho Actions; key được giới hạn trong authorized_keys.

Secret ngoài repository

Runtime đọc /opt/k4-day12-secrets/app.env, quyền 600; không commit API token hoặc Redis credential.

Container hardening

API chạy non-root, filesystem read-only, cap_drop: ALL, no-new-privileges và giới hạn log.

Network isolation

API chỉ bind 127.0.0.1:8000. Redis không map port ra host và chỉ được API truy cập qua private network.

Nginx & HTTPS

Nginx nhận traffic public trên 80/443, terminate TLS rồi proxy tới API nội bộ; certificate cần được gia hạn.

Firewall & persistence

UFW chỉ mở 22, 80, 443. Redis dùng named volume để dữ liệu còn sau khi container được recreate.

!
Lưu ý khi triển khai VPSChecklist trước khi đưa service lên production
  1. Trỏ DNS A record tới đúng IP VPS trước khi xin chứng chỉ HTTPS.
  2. Chỉ lưu private key trong GitHub Secrets; VPS chỉ nhận public key.
  3. Không mở cổng 6379 và không bind API trực tiếp ra 0.0.0.0:8000.
  4. Kiểm tra docker compose ps, logs, /healthz và /readyz sau mỗi lần deploy.
  5. Sao lưu volume Redis và file cấu hình trước khi nâng cấp; giữ image cũ để rollback.
  6. Theo dõi dung lượng đĩa, memory, certificate expiry và xoay token khi nghi ngờ bị lộ.
